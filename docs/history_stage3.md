# Этап 3 История пользователей для MVP

Этап готовит достоверные наблюдения архива и состояние обучения. Профили интересов
и поисковые алгоритмы реализуются далее. Наблюдения не являются показами,
кликами, подтверждёнными платежами или наградами бандита.

## Запуск

В Ubuntu/WSL из корня репозитория:

```bash
conda activate alpha
docker compose -f scripts/catalog-source.compose.yml up -d --wait
docker compose -f scripts/catalog-source.compose.yml exec -T db \
  psql -X -v ON_ERROR_STOP=1 -U alfa_ml -d alfa_course < scripts/sql/check_user_history.sql
python scripts/export_user_history.py
python scripts/build_user_history.py
python scripts/verify_user_history.py
python -m pytest backend/tests -q
```

Для временного разделения можно добавить
`python scripts/build_user_history.py --cutoff-month 2026-06`.
Это демонстрационный параметр, не рекомендуемая или подобранная дата тестирования.
Решение о cutoff принимается при планировании оценки качества.
До cutoff включаются только строго более ранние месяцы. Все записи месяца
cutoff остаются в наборе from_cutoff; пользователи и временные связи не
перемешиваются случайно.

Исходная база должна быть уже восстановлена. Команды не меняют исходные таблицы.
Каталог этапа 2 должен существовать и пройти проверку
`python scripts/verify_catalog_bundle.py`.

## Структура

- `backend/app/data_preparation/history_source.py`: отдельная разрешённая
  схема 15 таблиц. Каталожный EXPORT_COLUMNS не содержит пользовательских таблиц.
- `history_contracts.py`: наблюдения, теги, состояние обучения, отношения.
- `history_resolution.py`: контекстные идентичности и псевдонимы.
- `history_time.py`: месячная хронология и строгий cutoff.
- `user_history.py`: нормализация и проекции.
- `learning_state.py`: кандидаты продолжения без выдачи прав доступа.
- `history_audit.py`: независимые инварианты и агрегаты.
- `history_io.py`, `history_bundle.py`: локальные файлы, хеши, сборка и проверка.

Исходные выгрузки: `data/interim/history/<snapshot_id>/`, указатель CURRENT.
Результаты: `data/processed/history/<bundle_id>/`, отдельный указатель CURRENT.
Эти каталоги исключены из Git. Идентификаторы пользователей псевдонимны;
исходные UUID не следует считать анонимными данными или публиковать.

## Контракты результатов

| Файл | Содержание |
|---|---|
| observations.jsonl | Только принятые персональные наблюдения |
| unassigned_observations.jsonl | Разрешённая сущность, но отсутствует пользователь |
| rejected_observations.jsonl | Удалённые, неразрешённые или несогласованные сущности с причинами |
| profile_inputs.jsonl | Точная проекция принятых записей; исключены оценки с неизвестной/неверной шкалой |
| learning_state.jsonl | Текущее состояние по конкретному зачислению, без объединения потоков |
| evaluation_inputs.jsonl | Консервативная проекция с пригодной месячной хронологией |
| related_materials.jsonl | Отдельные отношения контента, включая нерешённые и самоссылки |
| evaluation_before_cutoff.jsonl / evaluation_from_cutoff.jsonl | При явно переданном cutoff |
| audit.json | Взаимоисключающая сверка строк и пересекающиеся признаки качества |
| manifest.json | Версии правил, source snapshot, точный каталог, код и хеши файлов |

Наблюдение содержит один исходный факт/состояние с устойчивым ID от пары
(source_table, source_record_id). Основные виды: enrollment_state,
lesson_progress, explicit_rating. user_key имеет пространство имён organizer.
RatingTags вложены в оценку и не размножают её строки. Наборы profile/evaluation
не являются дополнительными независимыми событиями.

## Разрешение сущностей

Прохождение разрешается только через CourseUserId → CourseUserBindings.Id →
UserId и CourseId с дополнительной проверкой связи курса и урока.

В UserRatings тип 8b440b1a-00c3-423a-9bae-3376475eb203 указывает на Lessons.
В RecommendedItems тот же тип обозначает Courses. Поэтому справочники типов
контекстные, каждое соответствие проверяется по членству ID.

Калькуляторы/страницы разрешаются через aliases.jsonl закреплённого каталога.
Оценка урока связывается с курсом по фактическому прогрессу пользователя, затем
по его зачислениям, затем по единственному курсу в каталоге. Если остаются
несколько курсов, оценка сохраняется на уровне урока без material_key.
Одна оценка никогда не размножается на все курсы.

Исключаются удалённые записи/сущности и групповые уроки. Оценки без UserId не
приписываются пользователю через IP, CreatedById или догадку.
Шкала проверяется через RatingGroupId и активные Ratings/RatingGroups.
Неизвестное значение сохраняется, но не становится сигналом профиля или
временной меткой. Числа шкалы не преобразуются в полезность или вероятность.
Маппинг положительных/отрицательных сигналов остаётся задачей этапа 4.

RecommendedItems использует полный составной ключ (Id, ItemId, ItemTypeId).
Id проверяется как исходный материал, ItemId с контекстом ItemTypeId — как
целевой. CourseId сохраняется исходным, не используется как предположительный
источник. Не найденные в каталоге сущности и самоссылки учитываются отдельно.

## Хронология и утечки

event_time имеет вид YYYY-MM. Исходные даты сохраняются отдельно, включая
пустые и противоречивые значения. Не создаются фиктивные дни, секунды или
порядок внутри месяца. completion_before_creation не переписывает дату.
Невалидные/бесконечные даты, неизвестный часовой пояс и неожиданная точность
помечаются, временная оценка таких записей запрещается.

Для прохождения используется Completed; отсутствие этой даты не восполняется
Created. Для оценки используется наиболее поздняя из Created/Modified:
текущий текст/значение оценки не переносится на более раннюю дату создания.
available_from_month не раньше даты регистрации этого наблюдения.

Состояния CourseUserBindings целиком исключены из временных меток: текущее
IsCompleted и LessonsCompleted не были обязательно известны при Created.
Когда курс многократно используемого урока определён с помощью текущих
пользовательских связей, историческая доступность такой атрибуции считается
неподтверждённой. Запись остаётся в текущем профиле, но исключается из временной
оценки. Уроковая оценка без material_key остаётся уроковым свидетельством;
оценивать по ней курс нельзя без отдельного доказанного разрешения.

Эта проекция не восстанавливает полный clickstream. Состояние удалённости,
тексты, шкалы и каталог доступны только в текущем snapshot. Использование
проекций для оценки требует раскрыть это ограничение и выбрать корректный
уровень задачи. Архив не предоставляет policy propensity или CTR.

## Продолжение и доступ

Состояние хранится по CourseUserBindings.Id. Дубликаты прохождения одного урока
не увеличивают список завершённых уроков. Расхождение исходного счётчика с
принятыми записями отмечается и не исправляется молча.

Кандидаты — до пяти незавершённых активных негрупповых уроков из нужного курса,
с учётом явной закрытости и будущего ClosedUntil. Order задаёт порядок кандидатов,
но не доказывает последовательное открытие: ParentGroupId, PassageMode и
ContentAccess не получают выдуманной семантики. next_lesson_id отсутствует;
сервис платформы должен подтвердить реальный следующий урок.

entitlement_granted всегда false. requires_access_check и
requires_progression_check всегда true. Известно закрытый курс не получает
кандидатов. IsPaid, подписка и состояние зачисления не заменяют проверку прав.
URL урока не выдумывается.

## Воспроизводимость и приёмка

Выгрузка повторно использует неизменяемый snapshot с теми же хешами.
Сборка включает в ID source snapshot, bundle каталога, версии, хеши кода,
конфигурацию cutoff и результаты. Публикация атомарна; ошибка не заменяет CURRENT.
Изменение содержимого без пересчёта манифеста обнаруживается.

Проверяются исходные и нормализованные значения, точные проекции,
отсутствие придуманных пользователей, корректные родители уроков, отсутствие
фальшивых наград/покупок, кандидаты и раздельные категории сверки.
Сумма accepted + unassigned + rejected равна числу исходных наблюдений.
Причины качества могут пересекаться, они не складываются как отдельные строки.

Новые библиотеки не нужны. Дополнительные сетевые проверки URL для этого этапа
не выполняются; он использует локальную базу и закреплённый каталог.
