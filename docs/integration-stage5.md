# Этап 5: события и обновление модели

Реальные рекомендации и события доступны при `VITE_RECOMMENDATIONS_SOURCE=api`. `decision_id` обозначает выданную подборку, `item_id` — выданную карточку, `impression_id` — подтверждённую клиентом видимость, `event_key` — идемпотентный идентификатор сообщения. Идентичность берётся из подписанной анонимной сессии сервера; чужие actor, session, item, material и impression не принимаются. Регистрация и подтверждённая аутентификация пока не связаны с actor.

Клиент подтверждает видимость, когда карточка непрерывно видна не менее секунды на 50% и вкладка активна. Это **сигнал клиента**, а не независимое доказательство чтения. Переход по ссылке после подтверждения фиксируется как клик. Клик до получения подтверждения сохраняется отдельно в `unattributed_clicks` с привязкой к карточке и сессии, без выдуманного показа и без награды. Один клик не считается доказательством загрузки внешней страницы: `material_open` публичным HTTP API пока отклоняется, пока нет доверенного callback от контролируемого источника. Пользовательское сообщение `purchase_confirmed` также отклоняется; реального платёжного адаптера пока нет.

`POST /api/v1/events/visibility`, `/events/action` и `/events/unattributed-click` требуют cookie и `X-CSRF-Token`. События с одним ключом и одинаковым содержимым возвращают тот же результат; повтор с изменённым содержимым или другим типом отклоняется. Обработчик и журнал reward используют транзакции и блокировку, поэтому параллельные повторы не обновляют модель дважды.

Клиент кладёт событие в ограниченный outbox `sessionStorage` **до** первой сетевой операции и повторяет отправку с тем же ключом и payload. Очередь хранит только путь, ключ, время и идентификаторы события/материала, без текста задачи, профиля и CSRF; материал по идентификатору может косвенно раскрывать интерес. После доставки или необратимого отказа запись удаляется. Лимит — 100 событий и до 7 суток, при открытом приложении выполняется повтор и обработчик `online`. Это уменьшает потери, но не гарантия после закрытия вкладки, смены сессии, при отключённом/переполненном хранилище или истечении срока. Если старая сессия утрачена, сервер не припишет событие новой.

## Обычная политика и worker

`RewardPolicy` из `ml` не изменена: награда созревает через 24 часа, окно атрибуции — 7 суток, значения click 0.1 и подтверждённого бесплатного открытия 0.15; включение проверенных платежей по умолчанию выключено. Открытый доступ сам по себе не доказывает нулевую цену: бесплатность учитывается только если в снимке явно известна нулевая цена и доступ открыт. Пока подтверждённого источника открытия нет, frontend посылает только click. Пользовательские события нельзя принимать за подтверждённую покупку.

Worker запускается отдельным процессом и использует ту же событийную БД, что API. Запуск из корня проекта после подготовки каталога, `.env` и БД по [этапу 4](integration-stage4.md):

```bash
set -a; source .env; set +a
# В .env: ALFA_RECOMMENDATIONS_ENABLED=true, ALFA_DEMO_FAST_LEARNING=false,
# секрет ALFA_SESSION_SECRET; для локального HTTP ALFA_SESSION_COOKIE_SECURE=false.
python scripts/migrate_events.py
python scripts/reward_worker.py --interval 30
```

В другом терминале с тем же окружением запустите `PYTHONPATH=backend uvicorn app.main:app --host 127.0.0.1 --port 8000`. Ещё в одном: `VITE_RECOMMENDATIONS_SOURCE=api VITE_API_BASE_URL=http://127.0.0.1:8000 npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173`. Укажите origin frontend в `API_CORS_ORIGINS`. Worker нужно держать запущенным; по умолчанию он не стартует сам внутри API. Опция `--once` выполняет один проход.

Миграция `0006_reward_projection` сохраняет версию проекции и причину каждой ревизии награды. Старые признаки бесплатности без подтверждённой цены переоцениваются без изменения исходных событий; ранее начисленная награда корректируется новой аудируемой ревизией. До такой проверки `replay` старой проекции отклоняется и API безопасно использует prior. Версия и причина участвуют в ID состояния модели. Миграция `0007_unattributed_clicks` добавляет отдельное хранение ранних кликов без reward. Обе применяются обычной командой `scripts/migrate_events.py`.

## Отдельная тестовая симуляция

**Только тест:** используйте событийную БД с точным именем `alfa_events_test`, `ALFA_DEMO_FAST_LEARNING=true` и `ALFA_RECOMMENDATIONS_ENABLED=true` одновременно в API и worker. Удобно после `source .env` выполнить `export ALFA_EVENTS_DATABASE_URL="$ALFA_EVENTS_TEST_DATABASE_URL"` и `export ALFA_DEMO_FAST_LEARNING=true`; затем запустить миграции, API, worker (`--interval 2`) и frontend как выше. UI явно показывает «Тестовое обучение»; решения и события помечены `simulated`, отдельная модель `demo-fast-linucb-v1` использует окно созревания 2 секунды. Обычный worker не обучается на таких событиях. Переключение обычного и тестового режима с прежним request key отклоняется с 409.

Для теста платёжной интеграции после симулированного показа можно взять `item_id` из ответа тестового API и выполнить:

```bash
python scripts/demo_test_payment.py --item-id <UUID_тестовой_карточки>
```

Команда работает только при включённом деморежиме, в `alfa_events_test`, для симулированной карточки с подтверждённым показом. Она создаёт **вымышленное тестовое уведомление**, не связывается с эквайрингом, не списывает деньги, не является продажей и не влияет на reward. `server_verified` в такой записи нельзя интерпретировать отдельно от `payment_environment=test` и `simulated=true`.

## Проверки и оставшиеся границы

Проверены PostgreSQL-тесты сессий, событий и наград, параллельные обработчики, восстановление состояния, пересчёт legacy-награды, изоляция тестового режима и отказ симулятора на рабочей БД. В headless Edge подтверждены баннер, видимость и клик с привязкой к одному показу; тестовый worker обновил модель, тестовый платёж награду не изменил. Отдельно проверен ранний клик без выдуманного impression. Текущие проверки и их команды приведены в отчёте задачи; перед дальнейшим релизом нужны реальные проверки прав PostgreSQL, устойчивости к закрытию вкладки, а также доверенные интеграции открытия и оплаты.

Критик самостоятельно проверил код, PostgreSQL-тесты, frontend-тесты и HTTP-поток, оценка **7/10**. Ограниченная браузерная и тестовая платёжная цепочка проверена исполнителем; реальные покупки, открытие внешнего сайта и доставку событий при любых отказах она не доказывает.
