# Инструкция тимлиду: запуск и демонстрация MVP

Это локальный интеграционный прототип. Рекомендации используют реальный каталог, BM25, признаки, prior и LinUCB; отслеживаются подтверждённая браузером видимость и клики. Тестовое обучение явно обозначено как симуляция. Подтверждения фактического открытия внешнего сайта и платёжного адаптера нет. Автоматическая доставка событий при закрытии вкладки не гарантируется. Регистрация не связана с анонимной идентичностью рекомендаций. Возможна выдача одной карточки, а доступность ссылок может быть неизвестна.

## Что потребуется

- Linux/macOS с Docker Compose, Python 3.12 и Node.js с npm (проверено на Node 18). Команды ниже выполняются из корня проекта в bash; свободные порты 55437, 55438, 8000 и 5173.
- Приватный доверенный архив PostgreSQL организаторов `alfa_course_hackathon.backup` **или** заранее подготовленные совместимые каталог `data/processed/catalog` и индекс `artifacts/retrieval`. Эти данные не входят в Git; запросите доступ у владельца. Архив может содержать персональные данные, не загружайте его и производные файлы в Git.
- Для *построения* каталога с нуля нужен закреплённый токенизатор: предоставленные архивы `e5-model.zip` и `e5-vectors.zip`, либо сеть для скачивания токенизатора. Веса E5 и семантические векторы для работы BM25 **не нужны**. Если каталога/индекса нет и недоступны исходные данные или токенизатор, реальный сценарий рекомендаций заблокирован; отдельно можно запустить обозначенный деморежим frontend.

## Установка и подготовка каталога

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt -r backend/requirements-catalog.txt
npm --prefix frontend ci
```

Если совместимые каталог и индекс уже предоставлены доверенным источником, поместите их по указанным выше путям и выполните `python scripts/build_retrieval_index.py --verify`. Проверка сверяет хэши и соответствие индекса каталогу и реконструирует поисковую матрицу; она не подтверждает подлинность источника. Для полной проверки `python scripts/verify_catalog_bundle.py` дополнительно нужны `data/interim/source_manifest.json` со всеми упомянутыми в нём исходными экспортами и `artifacts/e5-tokenizer` с закреплённым токенизатором; при наличии только каталога и индекса эта проверка недоступна. Индекс требует совместимых версий NumPy/SciPy/scikit-learn. Не перезаписывайте чужие файлы. При отсутствии готовых артефактов создайте каталог из доверенного архива в **новой** пустой рабочей копии:

```bash
mkdir -p data/raw
# Скопируйте предоставленный архив в data/raw/alfa_course_hackathon.backup.
python scripts/restore_catalog_source.py
python scripts/export_catalog_sources.py --compose-file scripts/catalog-source.compose.yml
# Один из вариантов подготовки токенизатора:
python scripts/prepare_tokenizer_from_archive.py --model-zip /path/to/e5-model.zip --vectors-zip /path/to/e5-vectors.zip
# Или при наличии сети вместо предыдущей команды: python scripts/prepare_catalog_tokenizer.py
python scripts/build_catalog_bundle.py
python scripts/verify_catalog_bundle.py
python scripts/build_retrieval_index.py
python scripts/build_retrieval_index.py --verify
docker compose -f scripts/catalog-source.compose.yml stop
```

Исходная БД каталога изолирована от двух БД приложения. Восстановление откажет при непустой исходной БД; ничего не удаляйте для повторного запуска без отдельного решения владельца. Для работающего BM25 семантическая модель E5 не используется; локальные векторы с текущим индексом не подтверждены как совместимые.

## Конфигурация и базы

```bash
cp .env.example .env
# Задайте в .env случайный ALFA_SESSION_SECRET и сохраните его между перезапусками:
python -c 'import secrets; print(secrets.token_urlsafe(32))'
# Для локального HTTP задайте ALFA_SESSION_COOKIE_SECURE=false,
# ALFA_RECOMMENDATIONS_ENABLED=true и ALFA_DEMO_FAST_LEARNING=false.
# Для безопасной среды замените примеры паролей на свои и согласуйте URL/Compose.
set -a; source .env; set +a
docker compose up -d --wait db
docker compose -f scripts/events.compose.yml up -d --wait db
python -m alembic -c backend/product-alembic.ini upgrade head
python scripts/migrate_events.py
```

Если меняете пароль событийной БД, задайте `ALFA_EVENTS_PASSWORD` для Compose и соответствующие пароли в `ALFA_EVENTS_DATABASE_URL` и `ALFA_EVENTS_TEST_DATABASE_URL`; изменение переменной само по себе не обновляет пароль уже созданного PostgreSQL volume. Значения в `.env.example` — только локальные примеры, секрет сессии оставлен пустым. `API_CORS_ORIGINS` должен содержать точный origin интерфейса. На HTTPS используйте secure cookie. Не коммитьте `.env`.

## Запуск и обычное демо

В отдельных терминалах активируйте `.venv` и выполните `set -a; source .env; set +a`, затем:

```bash
# Терминал 1
python scripts/reward_worker.py --interval 30
# Терминал 2
PYTHONPATH=backend uvicorn app.main:app --host 127.0.0.1 --port 8000
# Терминал 3: Vite не читает корневой .env автоматически
VITE_RECOMMENDATIONS_SOURCE=api VITE_API_BASE_URL=http://127.0.0.1:8000 npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173
```

Откройте `http://127.0.0.1:5173`, введите задачу, например «Как предпринимателю разобраться с НДС?», и заполните доступные поля анкеты. Дождитесь карточки, посмотрите объяснение и отметки об неизвестной доступности. Подержите карточку видимой не менее секунды и нажмите ссылку: будет записан клиентский сигнал показа и клик, а не подтверждённое открытие внешнего ресурса. Обновите страницу: в той же вкладке должны восстановиться анкета и ответ на прежний ключ запроса, если `sessionStorage` доступен. Для пустого результата попробуйте запрос вне тематики. Браузерная видимость не доказывает прочтения.

BM25 — основной путь и не зависит от весов E5: при отсутствии весов используйте эту же инструкцию. Если приватный каталог недоступен, можно запустить frontend с `VITE_RECOMMENDATIONS_SOURCE=demo npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173`: примеры будут явно вымышленными и backend/ML это не проверяет.

## Тестовое ускоренное обучение

В новом терминале активируйте `.venv`, загрузите `.env`, затем переключитесь только на тестовую БД:

```bash
set -a; source .env; set +a
export ALFA_EVENTS_DATABASE_URL="$ALFA_EVENTS_TEST_DATABASE_URL"
export ALFA_DEMO_FAST_LEARNING=true ALFA_RECOMMENDATIONS_ENABLED=true
python scripts/migrate_events.py
PYTHONPATH=backend python scripts/stage7_restart_smoke.py
```

Для интерактивного демо запустите API и worker с этим же тестовым окружением, как описано выше, задав worker `--interval 2`. После обычного демо откройте новую вкладку и заново заполните анкету, чтобы получить новый ключ запроса: повторное использование ключа из другого режима вызывает 409. Frontend покажет баннер «Тестовое обучение»; режим обрабатывает синтетически помеченные действия через две секунды, рабочая модель отделена. Скрипт выше создаёт тестовые события, запускает временный API и worker и проверяет сохранённое состояние. Подробности, в том числе симуляция платежного уведомления без реального платежа, — в [этапе 5](integration-stage5.md).

## Проверки

Создайте отдельную продуктовую БД `alfa_product_test` в локальном тестовом экземпляре PostgreSQL (на пустом локальном Compose: `docker compose exec -T db createdb -U "$POSTGRES_USER" alfa_product_test`; если база уже существует, повторно её не создавайте). Событийный Compose создаёт `alfa_events_test` при первоначальной инициализации. Укажите изолированные тестовые URL (никогда не исходную БД организаторов):

```bash
export ALFA_PRODUCT_TEST_DATABASE_URL='postgresql+psycopg://alfakurs:change_me@127.0.0.1:55438/alfa_product_test'
# ALFA_EVENTS_TEST_DATABASE_URL задан в .env; приведите оба URL к вашим паролям.
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m pytest backend/tests -q -rs
npm --prefix frontend test
npm --prefix frontend run build
```

Без тестовых URL часть PostgreSQL-тестов пропускается. Фактические результаты, команды для чистых миграций, сетевого перезапуска и границы качества приведены в [отчёте этапа 7](integration-stage7.md). Последний полный прогон: 277 backend/ML тестов, 21 frontend-тест и успешная сборка. Выдача нескольких карточек на реальном каталоге, подтверждение внешнего открытия, доступность ссылок и реальные платежи не подтверждены. Метрики продаж и конверсии не измерялись; аналитический экран может содержать демоданные.

## Ограничения, обнаруженные при ручной проверке

- Экран аналитики пока не подключён к данным: он показывает прочерки и сообщения о недоступности, даже если события видимости и кликов записываются. Конверсия в покупку и результаты сравнения алгоритмов на этом экране не рассчитаны.
- Рекомендации принимают свободную задачу без регистрации, но регистрация пока ограничена тремя готовыми задачами; регистрация не связана с анонимной сессией рекомендаций, а повторный вход после обновления страницы не реализован. Упоминание «деморежима» в сообщении об ошибке регистрации устарело.
- Поиск чувствителен к опечаткам: при локальной проверке «Ищу клиентв для b2b saas» дал пустую выдачу, а исправленный запрос «Ищу клиентов для b2b saas» вернул материал. Качество выдачи зависит от формулировки; автоматическое исправление опечаток не реализовано.
- Сохранённый индекс привязан к версиям NumPy, SciPy и scikit-learn. При ошибке `Incompatible retrieval/runtime version` создайте отдельный индекс в текущем окружении и укажите его путь в `ALFA_RETRIEVAL_INDEX_DIR`; не перезаписывайте чужие артефакты. Сборка и проверка описаны выше.
