# Инструкция по независимой оценке поиска этапа 5

Оценщик получает только blind_pool.json и не видит файлы rankings.json и evaluation.json до фиксации оценок. Данные организаторов и любые карточки с текстом остаются локально; не пересылать их третьим лицам или во внешние сервисы без разрешения организаторов. Для каждого материала оценивать только публичные свидетельства, формат и условия конкретного сценария. Материал в пуле не означает, что он пригоден для запроса.

Оценки: 0 — не помогает решить задачу или нарушает явное ограничение; 1 — касается соседней темы или помогает лишь частично; 2 — полезен для решения конкретной задачи, но не закрывает её полностью; 3 — прямо отвечает на задачу или предоставляет запрошенный инструмент. Название без достаточного публичного свидетельства не доказывает содержимое: использовать осторожную оценку и записать причину сомнения. Для устаревающих налоговых сведений учитывать заявленный период и не выдавать старые правила за актуальные. При неопределённом доступе или длительности не придумывать значения.

Создать pool_judgments.json в той же приватной папке как массив объектов с case_id, material_key и целочисленным grade от 0 до 3; каждая карточка пула должна иметь ровно одну оценку. Дополнительные поля assessor и note допустимы, но они не должны содержать персональные данные исходного архива. Вопросы и спорные оценки вынести в отдельный локальный журнал. Желательна повторная разметка пересекающейся подвыборки другим человеком с согласованием расхождений; указать число оценщиков, объём пересечения и метод разрешения расхождений в итоговом отчёте.

Тестовые сценарии, увиденные при подготовке системы, не являются закрытым независимым тестом. При необходимости подготовить новый набор сценариев и зафиксировать правила, код, версии индекса и порог до раскрытия ранжирований. NDCG@10 и pooled Recall@50 ограничены оценённым пулом. Оценка запросов без найденных полезных материалов требует отдельного раскрытия, а не заявления об отсутствии полезных материалов во всём каталоге.
