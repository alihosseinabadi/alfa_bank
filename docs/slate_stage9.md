# Этап 9 Формирование подборки

Из предварительно допустимых UCB-кандидатов выбираются максимум шесть уникальных материалов. Отклонение prior score от лидера ограничено relevance_gap. Повтор формата снижает балл на diversity_weight; явно заданные ограничения формата, цены, времени и URL проверяются до записи. Ссылка next_step должна совпадать с адресом материала; платная карточка помечается для проверки доступа.

Используется epsilon-greedy на последней доступной позиции: первые позиции детерминированы, их условная вероятность равна 1. На исследовательской позиции вероятность лучшего кандидата равна 1-epsilon+epsilon/N, каждого другого epsilon/N. Доступный набор уменьшается на каждом шаге. Seed создаёт доверенный сервис и закрепляет за actor/request_key до выбора; повтор с изменённым входом отвергается. Снимок решения содержит pool, оценки, параметры и seed; item содержит условную вероятность. replay_record восстанавливает выбор по записи. Seed и снимки следует хранить приватно.

Переход на prior при ошибке модели остаётся отдельной функцией этапа 8; HTTP/auth и проверка индивидуальных прав относятся к интеграции, поэтому продолжение обучения не выдаётся без отдельной проверки прав. IPS helper предназначен только для одношаговых распределений с проверяемой поддержкой; на исторических данных без propensity его не применять.

Запуск: PYTHONPATH=backend python scripts/simulate_slate_stage9.py. Симулятор использует упрощённые synthetic proxy, не реальные retrieval и prior. Результаты не доказывают изменения продаж. Для PostgreSQL-тестов задайте ALFA_EVENTS_TEST_DATABASE_URL на отдельную alfa_events_test и запустите pytest backend/tests/test_slate_stage9.py -q. Примените миграцию 0004 через scripts/migrate_events.py к отдельной базе событий.

## Граница для интеграции

services/recommendation_orchestrator.py: issue_recommendations принимает prior, уже отфильтрованный с k=50, retrieval batch и загрузчик совместимого состояния. Он сохраняет decision и возвращает список карточек в том же порядке, что и item ID. Если модель недоступна или несовместима, записывается детерминированный prior с ограничением запрошенного k. Выбранный seed наружу не возвращается. При отказе самой базы событий выдача не считается записанной и не должна выдаваться как залогированная; вызывающий сервис должен обработать ошибку.

Это внутренняя граница, не HTTP и не проверка аутентификации. caller обязан передать доверенный actor и применить реальные права и blocked_material_keys до построения prior. Тематическое разнообразие доступно в v2, если caller передаёт совместимый проверенный каталог: штраф за пересечение публичных тем сохраняется и воспроизводится. Вызов без каталога сохраняет форматную политику v1; его историческая семантика не изменена. E5 и весь ML не считаются принятыми до полной оценки релевантности.
