# Этап 6 Признаки и начальное ранжирование MVP

Реализован детерминированный ранжировщик допустимых кандидатов этапа 5.
Содержательная оценка доступных методов выполнена: см. docs/quality_stage56.md.
Инженерная основа принята критиком, практически полезное улучшение prior
не подтверждено; полная приёмка продукта остаётся открытой.

## Как связаны файлы

- ml/ranking_contracts.py: общий RetrievalBatch для четырёх методов поиска,
  признаки и итоговые карточки.
- ml/ranking_inputs.py: адаптеры SearchResult TF-IDF, кортежей BM25/E5 и RRF.
- ml/feature_registry.py: версия, 22 nullable-признака, маски и вектор из 45 чисел.
- ml/feature_engineering.py: проверка совместимости и вычисление наблюдаемых признаков.
- ml/prior_ranking.py: фиксированные веса, фильтры, порядок, причины и публичные цитаты.
- data_preparation/ranking_bundle.py: чтение каталога, профилей и прогресса,
  локальное сохранение результатов и версий.
- scripts/rank_materials.py: задача/профиль → до 50 кандидатов → признаки → первые 6.

Алгоритмы находятся под backend/app/ml и не импортируют FastAPI,
SQLAlchemy, сервисы или ETL. Обёртка работает с существующим каталогом
и индексом, не требует новой базы или зависимостей.

## Запуск

В корне репозитория, окружение conda alpha:

```bash
python scripts/rank_materials.py --task "Рассчитать НДС" --formats calculator --free-only
python scripts/rank_materials.py --method bm25 --task "Шаблон договора услуг" --formats document
python scripts/rank_materials.py --topics "Финансы" --time-minutes 15
python scripts/rank_materials.py --task ""
python scripts/rank_materials.py --export-registry
```

Пользователь с сохранённым профилем:

```bash
python scripts/rank_materials.py --user-key 'organizer:<UUID>' --task 'Как привлекать клиентов?'
```

user_key и идентификаторы уроков не печатаются. Продолжение в CLI
показывается количеством кандидатов и требованиями проверки прав/последовательности.
Флаг --formats отсутствует: наследуются сохранённые ограничения; --formats без
значений явно сбрасывает ограничение формата. Изменённый онбординг реального
пользователя сначала сохраняется через pipeline профилей.

По умолчанию используется доступный TF-IDF. Для E5/гибрида нужны совместимые
локальные веса и векторы, а также явный экспериментальный semantic threshold:

```bash
python scripts/rank_materials.py --method hybrid --task "Как наладить продажи?" --semantic-threshold 0.7
```

0.7 в команде — пример параметра, не откалиброванный рабочий порог.
Пути задаются --model-dir и --vector-dir. В текущей WSL-копии этих E5-артефактов
нет; молчаливой замены другим методом нет. Для E5 в этом CLI применяется
консервативный словарный gate 0.3, как у гибрида; это новая конфигурация
и её качество ещё не измерено.

## Политика и сохранение

Параметры PriorPolicy можно передать JSON-файлом через --policy.
--include-features добавляет в локальный вывод вектор и компоненты оценки.
--output-dir artifacts/prior-ranking атомарно сохраняет неизменяемый bundle
с ranking.json, policy.json, feature_registry.json и manifest.json.
Запись разрешена только под artifacts, data/processed или reports.
Эти данные локальные, исключены из Git и не являются журналом настоящих показов.

Публичная карточка платного/подписочного материала не даёт право на его тело.
Ранжировщик проверяет scope, допустимость по каталогу, формат, время, free_only
и переданный платформой blocked_material_keys до вычисления признаков.
Продуктовая авторизация и проверка ссылки на урок остаются обязанностью сервиса.
Продолжение обучения передаётся отдельно; entitlement не предоставляется.

## Ограничения и работа после завершения MVP

- Стартовые веса не обучены. Измеренный прирост относительно retrieval очень мал;
  на новом holdout доверительный интервал включает 0, success@5 не изменился.
- Отрасль сопоставляется только по явным меткам. Меток стадии и опыта материалов нет.
- Отрицательные оценки остаются мягким историческим свидетельством.
- Прогресс из архива не является актуальной проверкой доступа или точной хронологией.
- Не завершены независимая оценка этапа 5, проверка URL и полная реконструкция E5.
- До итоговой приёмки нужны независимые сценарии, сравнение ранжирования с исходной
  выдачей, NDCG@10/успех@5/pooled Recall, задержка и сквозные сценарии продукта.
- LinUCB, показы, события, обновление по наградам и HTTP-интеграция не реализованы
  этим этапом. Следующий этап 7 — надёжные показы и события.
