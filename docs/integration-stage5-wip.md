## Уже сделано

- Добавлены защищённые session/CSRF HTTP-маршруты `POST /api/v1/events/visibility` и `/api/v1/events/action`, связывающие действия с выданной карточкой, actor, сессией и показом. Показ — клиентское подтверждение видимости, а не серверное доказательство чтения. Повтор с тем же ключом идемпотентен.
- API-режим frontend подключён к реальным карточкам. IntersectionObserver подтверждает показ после непрерывной видимости не менее 50% в течение секунды в активной вкладке; клик отправляется только при наличии подтверждения. Тестовый ускоренный режим отображает заметную пометку симуляции.
- Внешний переход не объявляется фактическим открытием материала: `material_open` через публичный API пока отклоняется с 503; `purchase_confirmed` не принимается от клиента. Реального платёжного адаптера нет. Ранние клики до подтверждения видимости и события при длительном сетевом сбое могут теряться.
- Добавлены worker `scripts/reward_worker.py`, тестовая политика с отдельным model key и `simulated=True`, разрешённая только для БД `alfa_events_test`, и обычная политика с прежней задержкой. Миграция `0006_reward_projection` добавляет версию и причину ревизии; при пересчёте старых некорректных утверждений о бесплатности событие остаётся неизменным, корректируется ledger. Миграция уже применена к локальным `alfa_events` и `alfa_events_test`.
- Алгоритмы в `backend/app/ml` не менялись. Приватный каталог и индекс остались локальными и исключены из Git. Исходный архив не изменялся.

- Последний целевой запуск: 62 backend/ML-теста прошли, 2 предупреждения; `npm test` — 15 тестов прошли, `npm run build` успешна.
- В изолированной `alfa_events_test` проверена тестовая цепочка HTTP: решение → видимость → клик → повтор того же события → автоматическая reward 0.1 с флагом simulated. Это тестовые события, не реальные пользователи и не покупка.
