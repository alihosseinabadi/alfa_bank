# Этап 2 Подготовка каталога

Конвейер формирует канонические материалы и текстовые фрагменты для следующего
этапа поиска. Пользовательская история и обучение модели сюда не входят.
Исходные таблицы читаются без изменений. Реальный backup, выгрузки, содержимое,
артефакты и локальные отчёты не коммитятся.

## Окружение и запуск

Команды выполняются из корня репозитория в Ubuntu/WSL.

```bash
conda activate alpha
python -m pip install -r backend/requirements.txt -r backend/requirements-catalog.txt
# Для точного повторения проверенного окружения Python 3.11 Linux:
# python -m pip install -r backend/requirements-catalog.lock.txt
```

Поместить предоставленный организаторами архив в
`data/raw/alfa_course_hackathon.backup`. Локальная исходная БД отделена от
прикладной БД и не публикует порт на хост. Расширения из backup восстанавливаются
PostgreSQL 17. Скрипт восстановления отказывается перезаписывать непустую БД.

```bash
python scripts/restore_catalog_source.py
python scripts/export_catalog_sources.py --compose-file scripts/catalog-source.compose.yml
python scripts/prepare_catalog_tokenizer.py
python scripts/build_catalog_bundle.py
python scripts/check_catalog_urls.py --timeout 5 --retries 1 --workers 4
python scripts/build_catalog_bundle.py --url-cache data/interim/url_checks.jsonl
python scripts/verify_catalog_bundle.py
python -m pytest backend/tests -q
```

Подготовка токенизатора явно скачивает только `tokenizer.json` модели
`intfloat/multilingual-e5-base`, revision
`d128750597153bb5987e10b1c3493a34e5a4502a`.
Сборка работает с локальным файлом, проверяет хеш и не скачивает веса модели.
Реальные эмбеддинги и BM25 реализуются на этапе 5.
При повторном запуске с теми же входами, кодом, конфигурацией и результатами
проверки URL идентификаторы и файлы данных совпадают.

## Выходные данные и интерфейс следующего этапа

`data/processed/catalog/CURRENT` содержит ID последней успешной сборки.
Новая сборка публикуется только после прохождения проверок; существующая
папка сборки неизменяема. Неудачная обработка не заменяет CURRENT.

| Файл внутри сборки | Назначение |
|---|---|
| materials.jsonl | Все канонические материалы, включая исключённые, с исходными значениями и причинами |
| aliases.jsonl | Проверенное соответствие (source_table, source_record_id) → material_key |
| child_links.jsonl | Все связи курс–урок, порядок и исходные ограничения продолжения |
| content_blocks.jsonl | Очищенные блоки с происхождением и областью доступа |
| chunks.jsonl | Все подготовленные фрагменты; промежуточный набор, не публичный индекс |
| public_chunks.jsonl | Единственный вход публичного поискового индекса |
| entitled_chunks.jsonl | Вход отдельного защищённого индекса; требуется фильтрация прав до поиска |
| url_checks.jsonl | Наблюдения доступности, время, HTTP-код, конечный URL и ошибка |
| audit.json | Агрегированные проверки и ограничения покрытия |
| manifest.json | Snapshot, версии, параметры, хеши файлов, commit и хеши рабочего кода |

Каждый chunk содержит `passage:`, заголовок и текст. Лимит проверяется реальным
токенизатором с учётом специальных токенов. Цель — 360 токенов, максимум — 512.
Сначала используются границы абзацев; длинный абзац делится без потери текста.
Начальная версия не добавляет перекрытие: порядок и ссылки позволяют расширить
контекст при поиске без дублирования индекса.

Резолвер истории должен использовать aliases.jsonl и child_links.jsonl, сохраняя
тип исходной сущности. LessonId не является самостоятельной карточкой материала.
Рейтинг урока нельзя автоматически размножать на все курсы, которые его используют.

## Правила данных

- Пять основных типов используют проверенное объединение с ContentSettings.
  Добавлены Glossary и Calculators/CalculatorPages с отдельными правилами.
- Калькулятор и страница объединяются по одинаковому ID с проверкой URL,
  либо по единственному точному URL. Конфликт или неоднозначность останавливает
  сборку. Неразрешённый калькулятор без подтверждения публикации сохраняется,
  но исключается из выдачи. Все исходные идентичности остаются в aliases.
- Для Glossary и CalculatorPages принято явно отмеченное правило публичной
  вспомогательной страницы; это политика подготовки, а не извлечённое поле
  ContentSettings. Для production её следует подтвердить владельцем платформы.
- NULL именно в Courses.Cost означает нулевую указанную стоимость. Исходный
  пропуск и правило сохраняются. Подписка/оплата/закрытость учитываются отдельно.
  Для остальных типов неизвестная цена остаётся неизвестной.
- Неполные даты публикации сохраняются исходными строками; точный порядок
  исторических действий на этом этапе не восстанавливается.
- URL образуются только из предоставленных slug по явной таблице маршрутов
  kurs-routes-v1. Исходное значение сохраняется. Заголовки для URL не используются.
- Удалённые метки удаляются из тематических признаков. Словарь RatingTags не
  используется как словарь контентных Tags.
- Из HtmlContent и текстовых Params извлекаются абзацы, заголовки, списки,
  подписи. Скрипты, скрытая навигация, явно рекламные объекты Params и повторные
  рекламные абзацы исключаются. Остальные нетекстовые блоки учитываются в аудите.
- Для Articles.Content и Lessons.Content используется fallback, когда извлечённых
  блоков тела нет. Для подкастов/вебинаров индексируются только метаданные:
  расшифровок в этом наборе нет.
- Для документов сразу используются описания и блоки. Опциональный
  `--document-dir` принимает предоставленные локальные файлы с именем
  `<Files.Id>.<Files.Extension>`. Поддерживаются UTF-8 TXT, DOCX и PDF с проверкой
  формата и ограничением размера; нетекстовые PDF отмечаются. Удалённые Files
  не извлекаются. Внешние файлы автоматически не скачиваются.

## Доступ и проверка ссылок

Карточки и описания выгоды платных/подписочных материалов доступны публично.
Тело закрытого материала помещается только в отдельную область `entitled`.
Тексты всех уроков требуют точного разрешения
`course:<course-id>/lesson:<lesson-id>`, даже если источник отмечает урок как
пробный. Приложение должно выдать этот ключ только после проверки реальных
прав, закрытости и срока открытия урока. Один факт владения курсом недостаточен.
Эта версия не реализует сервис авторизации: она предоставляет его проверяемый
контракт и не раскрывает защищённый текст публичному индексу.

Проверка URL ограничивает время, повторы и параллельность, использует HEAD
и при необходимости потоковый GET без скачивания документа.
404/410 дают unavailable, ошибки сети/сертификата/5xx/429 — temporary_failure.
401/403 означают достижимую, но требующую доступа или блокирующую пробу страницу.
Успешный HTTP-код не подтверждает права или правильность содержимого.
Временно неответившие и непроверенные материалы сохраняются; unavailable
исключается из выдаваемых индексных наборов. Повторная проверка обновляет
наблюдение, не удаляя исходный материал. TLS-проверка не отключается.

## Критерии приёмки

Проверяются сверка всех строк через aliases, уникальность ключей, отсутствие
осиротевших принятых связей, сохранение связей уроков, разрешение происхождения
каждого chunk, разделение областей доступа, лимиты токенов и контрольные суммы.
Тесты используют искусственные записи. Реальные данные остаются локально.

Отдельно требуется содержательный просмотр выборки материалов по каждому
формату. Автоматические проверки не подтверждают релевантность поиска,
актуальность описаний или правила доступа реального сайта. Эти ограничения
фиксируются в отчёте проверки; поиск и авторизация не считаются реализованными
только на основании успешной сборки.
