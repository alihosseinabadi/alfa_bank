# Этап 5 MVP: состояние на 17 ноября 2026 года

Этап 5 — контентный поиск TF-IDF + косинусное сходство по реальному каталогу:
до 50 уникальных материалов под текущую задачу или интересы из RequestContext.
Этап частично реализован; окончательная оценка качества ещё не завершена.

## Уже выполнено

- Добавлены чистые ML-контракты, TF-IDF по русским словам и биграммам,
  нормализация регистра, ё/е и обозначения 1С.
- Публичные фрагменты объединяются до материала по максимальному score.
  Повторный текст удаляется до обучения IDF; порядок результатов детерминирован.
- Реализованы ограничения формата, бесплатного доступа и известной длительности.
  Неизвестная цена/длительность и неподтверждённая доступность URL отмечаются явно.
- Явная задача имеет приоритет над историей. Пустой запрос, слабое совпадение
  и отсутствие допустимых материалов дают уточнение без выдуманной релевантности.
- Результат содержит публичное свидетельство, источник, причину и переход
  по URL материала. Продолжение обучения передаётся отдельно с требованием проверки прав.
- Добавлены тематический baseline, расчёт метрик и скрипт оценки.
- Реализованы сохранение без pickle, контрольные суммы, совместимость версий,
  атомарная публикация и полная реконструкция индекса из каталога.
- Реальный индекс: 1444 материала, 9965 уникальных публичных фрагментов из 9982.
  Закрытые фрагменты и платные тексты уроков не включены.
- Проверены каталог, история и 7420 профилей предыдущих этапов.
  Прошли 118 тестов; две повторные сборки дали одинаковый ID индекса.
- Независимый агент заранее зафиксировал 20 искусственных сценариев
  (10 development / 10 test) и 39 начальных ручных оценок.
  Подготовлен слепой пул материалов двух методов. Данные и индексы остаются вне Git.

## Как запустить

Из корня репозитория в окружении conda alpha:

```bash
python scripts/build_retrieval_index.py
python scripts/build_retrieval_index.py --verify
python scripts/search_materials.py --task "Рассчитать НДС" --formats calculator --free-only --k 6
python -m pytest backend/tests -q
```

Оценка выполняется через scripts/evaluate_retrieval.py после завершения
локального pool_judgments.json. Не запускать --collect-only повторно поверх
зафиксированного benchmark без явного решения создать новую версию оценки.

## Русские словоформы в основном BM25

Основной `BM25Retriever` теперь использует общий анализатор
`backend/app/ml/ru_text.py` (`ANALYZER_VERSION=ru-stem-syn-v2`): NFKC и `ё`,
расширенные стоп-слова, Snowball-стемминг, защищённые термины (`НДС`, `юнит`,
`SQL`, …), детерминированный бизнес-тезаурус и фразовые концепты
(«поток клиентов» ≠ «денежный поток»). Одинаковая нормализация применяется к
индексным текстам и запросам; исходные публичные фрагменты не изменяются.

Отдельный `RussianStemBM25Retriever` остаётся для сравнения, но демо-путь
использует основной канал. Покрытие проверяется на зафиксированном наборе
`data/synthetic/retrieval_cases_v2.json` скриптом
`scripts/evaluate_demo_queries.py` и тестом
`backend/tests/test_demo_query_coverage.py`. Это проверка покрытия на
синтетическом каталоге, а не оценка релевантности и не доказательство
бизнес-эффекта. Опечатки анализатор не исправляет; видовые пары глаголов
Snowball объединяет не все.

## Гибридный поиск: BM25 + плотные векторы (17.11.2026)

Демо-путь больше не является чистым BM25. Он использует два канала по одному и
тому же публичному корпусу и взвешенную комбинацию их оценок:

1. **BM25** (`BM25Retriever`) — точная русская морфология, тезаурус и фразовые
   концепты из `ru_text.py`.
2. **Плотный канал** (`LsaRetriever`, `EMBEDDING_VERSION=lsa-tfidf-svd-v2`) —
   TF-IDF по тому же анализатору → `TruncatedSVD` (64 компоненты) →
   L2-нормализация. Косинус считается по настоящим векторам, а не по
   эвристике. В документ чанка добавлены описание материала, темы и теги —
   без них плотный канал видел только тело текста и терял смысл карточки.

Векторный датасет **строится вместе с каталогом** и сохраняется как версия:
`rows.jsonl`, `vocabulary.json`, `idf.npy`, `matrix.npz`, `components.npy`,
`vectors.npy`, `manifest.json` с SHA-256 каждого файла и `bundle_id`.
`LsaRetriever.load()` проверяет контрольные суммы, пересчитывает векторы из
матрицы и падает, если они расходятся с сохранёнными. В Docker датасет лежит в
именованном томе (`ALFA_EMBEDDING_DIR=/app/demo-bundles/embedding`), поэтому API
загружает ровно ту матрицу, которая была собрана с индексом, а не переобучает
её при старте.

Слияние (`DenseHybridRetriever`, `dense_weight=0.4`, `dense_ratio=0.25`) —
не RRF, а нормированная выпуклая комбинация: каждая шкала делится на свой
максимум в этом запросе, затем 60% веса у BM25 и 40% у косинуса. BM25-оценки
неограничены, косинус лежит в `[-1, 1]`, поэтому складывать их напрямую нельзя.
Оба канала всегда запрашиваются с пулом 50 кандидатов, а `k` применяется только
к итоговому списку — иначе порядок зависел бы от размера страницы.

Семантика уточнения сохранена: если BM25 не нашёл ни одного кандидата, плотный
канал может ответить сам только при сильном косинусе (≥ 0.5) и только на
запрос, который энкодер узнал. Запрос вне словаря даёт нулевой TF-IDF-вектор и
остаётся пустым, поэтому бессмыслица не превращается в рекомендацию.

Почему LSA, а не E5: веса приватной E5-модели в репозиторий не входят.
`backend/app/ml/e5_retriever.py` остаётся готовой заменой энкодера: смена
`LsaRetriever` на `E5Retriever` не требует менять fusion, признаки или
ранжирование. Пока весов нет, честно заявлять «E5» было бы неправдой, поэтому
UI и API называют канал `lsa-tfidf-svd-v2`.

## Ранжирование и LinUCB в preview (17.11.2026)

`POST /api/v1/catalogue/rank` возвращает полный каталог:

- `algorithm = hybrid-bm25-dense-prior-linucb-v1`;
- `dense_score` — косинус плотного канала (диагностика, не вероятность);
- `bandit_score` — оценка shared LinUCB, прочитанная **без записи решения**;
- `bandit_state`: `cold` (модель ещё не видела наград), `warm` (есть
  наблюдения, UCB смешивается с prior) или `unavailable` (БД/модель
  недоступны).

LinUCB влияет на порядок только когда модель `warm` и только внутри guard
`prior_score >= 0.7 × лучший prior`: кандидат не может быть поднят с нуля
только за счёт exploration. Preview не пишет impression, click или reward —
это read-only проекция serving-политики.
